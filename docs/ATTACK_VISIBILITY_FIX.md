# 攻撃演出の表示修正

対象は、近距離の弾が生成と同じ更新で命中・消去される経路と、短い光線・衝撃波が描画前の連続更新中に消える経路です。調査基準は `1b3b5e9d6a1003567bdf5ee96d62d687e314aea7` です。ユーザーのiPhoneで起きた症状と直接一致するか、ノーマルだけで発生するかは未確認です。

## 変更内容

- `GameWorld.updatePresentation` で表示だけを1描画につき1回更新します。呼び出しは `scene.ts` のゲーム処理の連続更新より前です。その連続更新で新たに作られた光線と衝撃波は、同じ描画の前に寿命を消費しません。
- 描画間隔が長い場合も短い演出を数回表示できるよう、表示用の1回の進み幅は0.05秒までに制限します。ゲーム時間の進み幅や遅延の処理は変更しません。
- レールパルス、散弾、共通のモジュール弾は、命中時に軌跡と小さな命中光を0.14表示秒残します。実際の弾は従来と同じ命中判定で即座に削除します。表示に速度・ダメージ・当たり判定はありません。小さな命中光だけを敵や地形の後に描画し、近距離で敵本体に隠れる状態を避けます。通常の弾・光線・敵の描画順は変えません。
- 一時停止、準備中、強化選択、ボス報酬では表示時間も停止します。ボス登場時と再出撃時には、既存の消去経路で残像も削除します。ゲーム終了時は結果画面の背景として停止し、タイトルへ戻る際などにシーンが破棄されると削除します。表示は既存の光線・衝撃波の個数上限に従います。

攻撃力、命中範囲、連射間隔、敵の生成、回避、停止針、レベル、スコア、ランキング、モード別の仕様は変更しません。ノーマルと無限の共通処理に適用します。

## 再発確認

`pnpm test:rules` に `GameWorld.presentation.test.ts` を追加しました。ゲーム本体とBabylon.jsのNullEngineを実行し、両モードで近距離命中、遠距離の飛行、0.2秒・1秒の連続更新、モジュール弾、停止・再開、ボス移行時の消去経路、再出撃、個数上限、表示更新の有無によるゲーム状態一致を確認します。命中光だけが専用の描画順を使い、通常の弾は元の順序を保つことも検査します。

元の実装では、新規23テスト中21テストが失敗して表示前消去を再現しました。修正後は既存52テストと新規23テスト、計75テストが成功しています。型検査・ビルド・差分の空白検査も成功しました。
